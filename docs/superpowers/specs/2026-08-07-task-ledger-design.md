# NextX 任务台账设计

**状态：** 待用户复核  
**目标：** 用一份可持续维护的文档准确回答“已经实现什么、当前受阻什么、接下来做什么”。

## 权威边界

`docs/TASKS.md` 是当前任务状态的唯一权威台账。已有实施计划和产品规格保留为历史设计依据，不再用其中的复选框表示实时进度。README 只链接台账，不复制任务状态。

## 内容结构

台账依次包含：

1. 当前版本、更新时间和维护规则。
2. 已完成任务表。
3. 受阻任务表。
4. 待办任务表。
5. 状态变更记录。

任务字段固定为：`ID`、`模块`、`任务`、`优先级`、`状态`、`验收或证据`、`下一步`。

## 状态口径

- `已完成`：功能和必要验证都已存在，证据链接到代码、测试、文档或提交。
- `受阻`：实现路径明确，但当前依赖外部认证、用户决策或外部状态。
- `待办`：尚未开始且具有明确价值；纯设想不进入台账。

完成项按产品纵向能力汇总，不把每个源码文件拆成一个任务。待办只记录已经在产品架构中明确的演进项，避免把路线图变成无限愿望清单。

## 维护规则

- 每次功能合并时同步更新台账和状态变更记录。
- 状态改变时保留同一个任务 ID，不重新创建同义任务。
- `已完成` 必须有可检查证据；`受阻` 必须写解除条件；`待办` 必须写进入条件。
- 不在台账保存负责人、工期和发布日期，直到项目真正进入多人协作。

## 初始覆盖范围

首版台账覆盖 Self、Signal、Grok、Bookmarks、Today、Analysis、Decision、Artifact、Outcome、Weekly Review、Agent Skill、Obsidian、安装调度、可靠性、性能和开源准备。
